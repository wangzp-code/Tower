# 美术交付与 QA/性能验证流程

## 1. 美术交付流程

### 1.1 目录规范
- `Assets/Art/`：所有原始美术资源（角色、怪物、UI、特效、图标）。
- `Assets/Textures/`：纹理贴图资源。
- `Assets/Shaders/`：自定义着色器。
- `Assets/Prefabs/`：运行时使用的预制体。
- `Assets/Resources/`：运行时加载资源。

> 保持目录扁平、避免混乱，使用 `Assets/Art/<类型>/<用途>/` 的分级结构。

### 1.2 命名规范
- 统一使用小写 + 下划线，例如 `enemy_dog_idle.png`、`ui_button_primary.psd`。
- 资源类型前缀：`ui_`、`icon_`、`fx_`、`char_`、`monster_`。
- 版本号使用后缀，而不是覆盖原文件，例如 `ui_button_primary_v2.png`。

### 1.3 质量与规格
- 贴图尺寸按照 2 的幂次方排列（`128x128`, `256x256`, `512x512`）。
- UI 元素优先使用 `32`/`64`/`128` 等纹理尺寸。
- 生产时保存 `PSD`/`AI` 源文件，并导出 `PNG`/`TGA` 作为工程资源。
- 贴图压缩：移动端优先 `ETC2`/`ASTC`，桌面端使用 `DXT5` 或 `BC7`。

### 1.4 版本控制
- 资源文件与 `.meta` 一起提交。
- 大文件建议使用 Git LFS；如果未启用，请将大体积资源分类到独立分支或外部存储。
- 每次提交需附带变更说明：`新增 UI 按钮图标、优化战斗特效、清理未使用贴图`。
- 美术资源只提交最终版，避免大量中间文件进入主分支。

### 1.5 流程建议
1. 设计阶段：先确定视觉风格、配色、字体规范。
2. 版本迭代：初版 -> 调整 -> 优化 -> 终版。
3. 集成前进行资源检查：分辨率、压缩、命名、元数据完整性。
4. 在测试分支中校准渲染效果后再合并到主分支。

## 2. QA 与移动端性能验证流程

### 2.1 性能验证指标
- 帧率（FPS）：目标 60 FPS，低于 45 FPS 说明需要优化。
- GPU 内存：贴图、帧缓冲、RT 占用情况。
- CPU 时间：脚本、UI、物理、渲染各项耗时。
- App 包大小：资源压缩和纹理体积控制。
- 运行内存：Mono 堆和总分配内存。

### 2.2 测试步骤
1. 打开 `PerformanceManager` 并检查当前质量设置。
2. 在目标设备上运行真实战斗场景。
3. 使用编辑器工具生成性能报告。
4. 记录帧率波动、关键场景内存峰值、是否出现卡顿或丢帧。
5. 对高负载场景（Boss、粒子特效密集、UI 动效）重复验证。

### 2.3 目标设备建议
- Android 中低端机型
- iOS iPhone 手机
- 桌面低配模式

### 2.4 优化方向
- 开启 GPU Instancing（`PerformanceManager` 支持）。
- 降低 `maxVisibleMonsters`。
- 关闭不必要的后处理效果：`SSAO`、`Motion Blur`、`Depth of Field`。
- 降低纹理质量、抗锯齿、分辨率缩放。
- 合理使用粒子数量与生命周期。

### 2.5 报告与验证文档
- 生成报告文件：`Assets/OptimizationReports/performance_qa_report.txt`
- 记录测试机型、测试场景、结果数据、结论与修复建议。
