# 视觉精品化升级 —— 需求规格说明

> **目标**: 将生物朋克 (Bio-Punk) 风格 Roguelike 的"游戏内"界面从"程序生成+基础描边"水平，提升到精品手游质感。

---

## 1. 现状盘点

### 已具备的资产 & 基础设施（代码级完备度 70%）
- **6 个自研 Shader**（均有对应 Material 管理）:
  - `ParasiteBackground` — FBM 噪音 + 粒子 + 视差背景
  - `GradientHealthBar` — 渐变血条 + 边框 + 发光
  - `GlowingButton` — 呼吸光晕按钮
  - `ParasiteDissolve` — Fresnel 边缘发光溶解
  - `UIBreakdown` — 抖动/色差/扫描线故障效果
  - `PollutionSpread` — 污染扩散扭曲
- **完整的色彩 & 参数体系**: `ParasiteTowerColorScheme` (90+ 语义色) + `ParasiteTowerArtOptimization` (UI/怪物/VFX 配置类)
- **后处理雏形**: `BioPunkPostFX`（暗角 + 胶片颗粒，污染时增强）
- **艺术资源**: 6 张 floor_bg 图 + 44 怪物 Icon + 5 职业 Icon + 菜单/弹窗背景图
- **地图渲染**: 13×13 格子程序化生成，墙/地板/怪物/出口/事件各有独立渲染逻辑 + Outline 呼吸

### 显著缺失的精品化元素
| 缺失项 | 影响面 | 严重性 |
|---|---|---|
| 战斗界面无粒子特效（攻击闪光、命中火花、伤害数字） | 战斗 | 🔴 高 |
| ParasiteBackground Shader 未实际挂用 | 探索/战斗背景 | 🔴 高 |
| Blooom / 扫描线全局氛围缺失 | 全局 | 🟡 中 |
| 玩家/怪物角色卡片无动态光效 | 战斗 | 🟡 中 |
| HP/EP/Possess 进度条动画 & 发光不足 | 战斗 UI | 🟡 中 |
| UI 过渡动画缺失（按钮按下、面板展开） | 全局 | 🟡 中 |
| 探索地图格子无描边/光效（仅色块区分） | 探索 | 🟠 次 |
| 污染度视觉反馈不明显（仅 BioPunkPostFX 弱关联） | 全局 | 🟠 次 |

---

## 2. 升级目标

### 核心体验：生物朋克的"危险美感"
- **背景**: ParasiteBackground Shader 替换纯色/图片，动态噪音 + 粒子流动，营造"活的"生物膜氛围
- **战斗**: 双方角色卡片发光呼吸 + HP bar 光流动画 + 攻击命中粒子 + 伤害数字飞出 + Possess 进度环脉冲
- **探索**: 格子描边发光 + 玩家光标呼吸光 + 出口金色脉冲 + 怪物/事件 Outline 更亮 + 迷雾边缘柔和
- **全局**: BioPunkPostFX 扩展扫描线 + 污染红光 + 按钮点击反馈 + 卡片入场动画

### 非目标 (不做)
- 不引入新的第三方美术资源（现有资源够用）
- 不重构玩法逻辑（UI 层独立于游戏系统）
- 不改成 3D / Shader Graph / VFX Graph（纯代码实现）

---

## 3. 验收标准

### AC1 — 探索地图视觉层次
`rule`: 玩家、怪物、出口格子应与地板有清晰的视觉分离（背景 Shader 动态 + 格子描边 + Outline 发光可区分）
`rubric`: 视觉层次评分 (0-5)
- 0 = 色块糊在紫背景上
- 3 = 色块有颜色区分但无动态
- 5 = 格子描边 + Outline 呼吸 + 背景动态 + 玩家光标光效

### AC2 — 战斗界面精品化
`rule`: HP/EP Bar 使用 GradientHealthBar Shader 并具有光流动画；攻击按钮按下有视觉反馈；Possess 进度有脉冲光
`rubric`: 战斗界面精美度评分 (0-5)
- 0 = 静态色块 + 文字
- 3 = HP bar 有渐变但无光流；按钮点击无反馈
- 5 = HP bar 光流动画 + 攻击命中粒子 + 伤害数字 + 角色卡片发光呼吸

### AC3 — 全局 Bio-Punk 氛围
`rule`: 进入战斗/探索界面后 BioPunkPostFX 应展示暗角 + 扫描线，污染度上升时红光增强
`rubric`: 氛围营造评分 (0-5)
- 0 = 完全无后处理
- 3 = 只有暗角
- 5 = 暗角 + 扫描线 + 污染红光脉动 + 背景 Shader 动态噪音

### AC4 — 代码可维护性
`rule`: 所有 Shader/动效/粒子逻辑集中在 `VisualEffectsManager` 或类似独立组件，不侵入核心游戏系统
`rule`: 新增代码不改变任何现有编译行为（现有 CS0723/CS1503 历史问题已修复）

### AC5 — 性能约束
`rule`: 单 Canvas 帧生成/更新代码控制在 5ms 内（UI 层，不影响游戏逻辑）
`rule`: 粒子/光效只在需要时激活（不常驻 Update）
